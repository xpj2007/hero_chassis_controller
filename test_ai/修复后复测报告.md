## 0. 摘要

| 修复 | 结果 |
|---|---|
| **方案 A**：`odom_rest_enter_threshold 0.20 → 1.20`（exit 1.50，debounce 0.05） | **生效**。mode0 `static_b` 的 odom 从 **381.5 mm / 44.96°** 降到 **33.8 mm / 3.73°**，最终航向 **71.9° → 31.2°**；“PID 停、轮子空转、odom 积分”的 bug 消失。 |
| **2.1 方案 1**：`pid_rest_rot_enter_threshold: 0.3`，PID 静止判断增加 `|-ωlf-ωlb+ωrf+ωrb|` 旋转门限 | **部分生效**。直行静置完全不变（0.8 mm）；stop5 22.0→9.4 mm、stop6 20.8→4.8 mm，main `max_xy 1.994→0.999 m`、`rmse_xy 0.721→0.459 m`；但 `static_b` 的**机体 yaw 仍 -11.35°**（修复前 +10.29°，符号翻转），main 最终航向 **36.4°**（修复前 15.8°、旧 34.9°），最终位置 0.627 m。0.3 的门限不足以阻止 circle 停转后的车体 yaw 惯性。 |

**结论**：
- odom 门限 bug 已修好，mode0 的 381 mm/45°/71.9° 不再出现；mode0 最终 0.420 m/31.2°，已略优于旧 `mode0_short` 的 0.454 m/33.0°。
- 旋转门限改善了停止段位置和 max/rmse，但**没有消除** `static_b` 的机体 yaw（~11°）；main 的最终航向因 yaw 符号翻转反而从 15.8° 变成 36.4°。要真正压住它，需要更低门限（如 0.15）/目标为 0 时的 yaw 阻尼，或 IMU yaw。
- 直行静置 0.8 mm、stop1 横向 1.2 mm 保持；标定 k/r 未动。

## 4. 结论与下一步

1. **odom 门限修复有效，建议保留**：`odom_rest_enter=1.20` 让 odom 在轮速 <1.2 时冻结，覆盖了“PID 已停、轮子空转”的 0.2~1.0 窗口；mode0 的 381 mm/45° 和最终 71.9° 都消失。
2. **旋转门限 0.3 只解决了一半**：
   - 它让 stop5/6 的位置、main 的 max/rmse 明显变好，直行静置不受影响；
   - 但 `static_b` 的机体 yaw 仍在轮速降到 0.3 以下后继续 ~10°，最终航向没有真正下降（main 36.4°、mode0 31.2°，旧基线 34.9°/33.0°）。
   - 根因：0.3 是**轮速的旋转分量**，轮子停住 ≠ 车体停住；circle 停转后的角动量/接触让车体继续转，PID 已经闩锁关闭。
3. **下一步（按代价从低到高）**：
   - 把 `pid_rest_rot_enter_threshold` 从 **0.3 降到 0.15~0.2**，让 PID 更晚闩锁、多刹一点；代价是直行静止的 latch 可能略晚/略抖，需要复测 `static_a`。
   - 目标全 0 且检测到车体 yaw 仍大时，加一个**短时 yaw 阻尼**（对四轮 yaw 分量施加反向力矩），不需要 IMU 也能压住一部分；需要新增增益。
   - 根治仍是旧报告的 **IMU yaw**：静止时用 IMU 的 yaw rate 判断“车体是否真的停”，并做 yaw 阻尼/校正；单靠轮速/单 k 无法区分“轮停车体转”。
4. 旧报告的 P0/P1（`cmd_vel` 看门狗、TF z=0、1 kHz、mode1 TF、IMU）本轮仍未改；本报告只验证这两处修复。
